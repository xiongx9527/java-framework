# TinyEngine 模板创建应用修复设计

## 问题

通过模板创建应用时，接口 `/app-center/api/app-template/create` 返回 500，并出现两个错误提示，其中一个为空白。

已确认的根因：

- 创建请求继承模板的应用编码，写入 `t_app` 时触发应用编码唯一索引冲突。
- 模板复制通过带应用角色校验的页面服务读取源模板；当前用户不是模板成员时会被拒绝，即使模板在同一租户且允许公开使用。
- 全局 HTTP 层和模板详情组件分别显示同一个请求错误；组件将错误对象直接作为消息渲染，产生空白提示。

## 设计

### 应用编码

- 模板创建表单增加必填“应用编码”，与应用中心普通新建应用保持一致。
- 编码只能包含英文、数字、下划线和中划线，最大长度 20。
- 前端提交用户输入的编码，不再复用模板编码。
- 后端在写库前校验编码非空、格式合法且在当前租户内唯一；冲突返回稳定业务错误，不暴露 SQL 异常。

### 模板内部复制

- 后端先验证源应用是当前租户内的模板。
- 读取源模板页面属于模板复制服务的内部操作，通过 Mapper 读取，不要求操作者拥有源模板应用角色。
- 目标应用先创建 Owner 角色，再通过现有页面服务写入目标数据；目标应用写操作继续接受正常权限校验。
- 事务内任何复制步骤失败时，目标应用和角色数据全部回滚。

### 错误提示

- 请求失败由全局 HTTP 层显示一次错误提示。
- 模板详情组件只负责收敛 Promise，不能再次弹出同一错误。
- 成功行为保持现有确认框，不改变跳转流程。

## 测试

- 服务测试证明模板编码不会被继承，用户输入的新编码被保存。
- 服务测试证明重复编码在写库前被拒绝并返回业务错误。
- 服务测试证明无源模板角色的当前用户仍能复制同租户模板。
- 服务测试证明新应用创建 Owner，复制失败时事务回滚。
- 组件测试证明失败请求不触发第二个 Notify，成功行为保持不变。
- 在线测试使用真实模板创建应用，接口返回 200，数据库中应用编码和 Owner 正确，并且页面只显示一次结果提示。

## 交付边界

- 本修复单独提交。
- 不修改 AI 鉴权与应用成员入口设计。
- 不提交构建产物，不清理工作区其他未完成改动。
