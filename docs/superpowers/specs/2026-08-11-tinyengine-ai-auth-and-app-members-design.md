# TinyEngine AI 鉴权与应用成员入口设计

## 背景

TinyEngine 当前存在两个独立问题：

1. 机器人模型配置完成后，请求 `/tiny-engine/app-center/api/chat/completions` 返回 401，前端全局拦截器清除登录令牌并跳转登录页。
2. 应用角色后端能力已经存在，但应用中心没有可发现的成员管理入口。

两部分独立实现、测试和提交，避免扩大单次变更范围。

## AI 鉴权修复

### 根因

- 当前 19080 运行实例通过命令行关闭了 `fw.plus.tiny-engine.ai.enabled`，AI Controller 未注册。
- 机器人模型客户端和 TinyEngine 登录鉴权都使用 `Authorization` 请求头。模型 Key 与登录令牌相互覆盖，无法在同一个后端代理请求中同时表达两种凭据。
- 全局 HTTP 拦截器将所有 401/403 都解释为 TinyEngine 登录失效。因此上游模型鉴权失败也会清除 `engineToken`。
- 样例配置中的模型 Base URL 不是已经验证可用的地址。

### 数据流

1. 浏览器使用 `Authorization: Bearer <engineToken>` 访问 TinyEngine 后端代理。
2. 模型 API Key 作为代理请求体字段传递；如果启用密钥加密，则传递 `EKEY_` 令牌。
3. TinyEngine 认证过滤器只校验登录令牌。
4. AI Controller 从请求体解析模型凭据，移除敏感字段后再调用上游 OpenAI 兼容接口。
5. 上游模型错误以模型调用错误返回，不触发 TinyEngine 的重新登录流程。

### 配置

- 启用 TinyEngine AI、Web 和 Chat 能力。
- 启用所需 LangChain4j 模型模块。
- 样例模型 Base URL 使用 `https://gpt.fufu666.top/v1`。
- 不在设计文档、测试输出或提交消息中记录真实 API Key。

### 错误处理

- TinyEngine 登录令牌缺失或无效：返回 401，前端进入登录页。
- 模型 API Key 缺失：机器人设置区提示补充 Key，不发送请求。
- 上游模型 API Key 无效或上游返回 401/403：显示模型调用错误，保留 TinyEngine 登录状态。
- AI Controller 未启用：启动验证必须失败，不能以 404/401 作为可接受降级。

## 应用成员入口

### 入口与权限

- 在应用中心每个应用的操作区增加“成员管理”入口。
- 入口仅对当前应用的 `app_owner` 和 `app_admin` 可见。
- `app_dev` 不显示成员管理入口，也不能通过接口执行成员管理操作。

### 成员管理界面

- 展示成员、账号和应用角色。
- 支持添加成员、修改角色和移除成员。
- 使用现有成员接口，不另建重复的数据模型或权限体系。
- 成员操作完成后刷新当前应用成员列表，不刷新整个应用中心页面。

### 业务规则

- `app_owner` 唯一且不可分配、修改或删除。
- `app_owner` 和 `app_admin` 可管理应用成员。
- 操作者不可操作自己。
- 同一应用中同一用户只能添加一次。
- 前端按规则禁用或隐藏不可用操作；后端继续作为最终权限边界。

### 交互与错误处理

- 添加重复成员、越权操作、操作自己和 Owner 保护错误使用明确消息展示。
- 列表加载失败保留入口和重试能力，不将业务 403 解释为登录失效。
- 成员管理使用独立弹窗或抽屉，不进入新的营销式页面，也不嵌套卡片。

## 测试与验收

### AI

- 单元测试证明代理请求同时携带 TinyEngine 登录凭据和模型凭据，且二者不共用请求头。
- 单元测试证明上游模型 401/403 不会触发 TinyEngine 退出登录。
- 启动后使用真实登录令牌请求本机 Chat Completions，返回有效模型内容或 SSE 完成标记。
- 浏览器发送“你好”后停留在当前页面并显示模型回复。

### 应用成员

- 组件测试覆盖 Owner/Admin 可见入口、Dev 不可见入口。
- 组件测试覆盖列表、添加、改角色、删除及所有禁用规则。
- API 合同测试覆盖角色权限和错误语义。
- 浏览器分别使用 Owner、Admin、Dev 验证入口与操作权限。
