# README 小黑插图设计

## 目标

在根目录 `README.md` 已有四张深色技术型 SVG 的基础上，追加三张 Ian 小黑风格正文插图。插图用于解释核心认知，不替代现有架构、生态和构建流程图，也不重写 README 的信息结构。

## 范围

- 保留 `assets/readme/hero.svg`、`architecture.svg`、`ecosystem.svg` 和 `build-flow.svg`。
- 新增三张 16:9 PNG，保存到 `assets/readme/fw-plus-illustrations/`。
- 在根 README 的项目概览、Magic-API 资源模型和样例项目三个位置分别嵌入一张图。
- 不修改模块 README、Java 代码、POM、Comet 变更或其他现有工作区内容。
- 不提交生成提示词、临时预览或失败候选图。

## 视觉关系

现有深色 SVG 是严谨的工程事实层，负责项目身份、架构、能力分类和构建顺序。新增白底小黑插图是认知解释层，负责在长篇技术内容中形成阅读停顿，并用具象隐喻解释模块组合、动态资源和统一验证。

两套视觉不互相替换：SVG 保持技术、紧凑、确定性；PNG 保持白底、手绘、留白和轻微荒诞感。

## 配图设计

### 1. 模块化底座

- 文件：`assets/readme/fw-plus-illustrations/01-modular-foundation.png`
- 插入位置：`项目概览` 的层级表格之后、`快速开始` 之前。
- 核心意思：Core 提供承重基础，Boot、Cloud 和 AI 按需组合，Samples 承担整体验证。
- 结构类型：概念隐喻。
- 画面：一张歪斜但可工作的低科技装配台，Core 是厚重底座，Boot、Cloud、AI 是形状不同的可插拔部件。小黑站在装配台中央，认真拧紧关键连接件。
- 建议标注：`统一依赖`、`自动配置`、`按需组合`。
- 禁止：正式分层架构图、整齐卡片、复刻现有 SVG 的节点轨道。

### 2. 动态资源柜

- 文件：`assets/readme/fw-plus-illustrations/02-dynamic-resources.png`
- 插入位置：`Magic-API 资源模型` 的资源说明与安全提示之后、`样例项目` 之前。
- 核心意思：外部配置、脚本、任务和模板通过资源模型进入运行时，配置类资源与动态脚本具有不同生效方式。
- 结构类型：系统局部。
- 画面：一个带抽屉、摇柄和少量管道的怪异资源柜。标有配置、脚本和任务的资源从抽屉进入，小黑转动核心摇柄，另一侧打开一扇表示运行能力的小门。
- 建议标注：`配置`、`脚本`、`任务`、`动态加载`。
- 禁止：真实控制台、密集数据源图标、正式流程箭头、任何凭据或连接地址。

### 3. 样例验证台

- 文件：`assets/readme/fw-plus-illustrations/03-sample-verification.png`
- 插入位置：`样例项目` 的 AI Samples 表格之后、`开发与维护` 之前。
- 核心意思：Boot、Cloud 和 AI 样例通过统一入口验证层间依赖与组合结果。
- 结构类型：概念隐喻。
- 画面：一台低科技机械震动验证台承载三组不同形状的组件。小黑拉下测试杆并观察怪表盘，组件保持稳定，输出统一验证结果。
- 建议标注：`Boot`、`Cloud`、`AI`、`统一验证`。
- 禁止：CI 截图、测试报告界面、盖章工具箱、正式流水线图。

## 统一生成约束

- 16:9 横版 PNG，纯白背景。
- 黑色细手绘线稿，线条轻微抖动，不使用阴影、渐变、纸纹或复杂背景。
- 主体占画面约 40%-60%，至少保留 35% 空白。
- 小黑为黑色实心、白点眼、细腿、冷静空表情，并承担核心动作。
- 每张图只表达一个核心结构，最多使用四个短标注。
- 红色仅用于重点或结果，橙色仅用于主动作或路径，蓝色仅用于补充状态。
- 不添加左上角标题，不出现 PPT、课程页、商业矢量插画或儿童卡通效果。
- 不复刻 Skill 示例中的传送带、素材鱼、三层拉线、承接路线或盖章工具箱构图。

## README 嵌入

每张图使用居中 HTML 图片标签嵌入，宽度为 `100%`，并提供能够独立说明核心意思的中文 `alt` 文本。图片失效时，README 原有标题、正文、表格和命令仍然完整可用。

## 验证标准

1. 三个 PNG 均为 16:9、非空、可由 README 相对路径访问。
2. 每张图都通过小黑 Skill 的 QA checklist：白底、留白、小黑承担动作、标注简短、非 PPT、非旧案例复刻。
3. 在约 900px GitHub 内容宽度和 360px 窄屏宽度下检查可读性、裁切和视觉密度。
4. README 审计通过，所有本地图片引用存在。
5. `git diff` 仅包含本次新增 PNG 和三个 README 嵌入点，不覆盖现有 SVG 或其他用户改动。

本次只生成、筛选、保存并嵌入三张最终插图，不提交、不推送、不创建 PR，除非用户另行明确授权。设计文档按 brainstorming 流程单独提交，便于与当前未提交的 README 和开发改动隔离。
