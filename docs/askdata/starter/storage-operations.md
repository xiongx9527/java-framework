# 存储迁移、排障与验证

本页补充 `storage-matrix.md` 的运维步骤。默认内存实现只适合单机开发；集群必须显式选择共享状态、共享向量和可查询审计存储。

## 迁移 runbook

1. 记录旧存储版本、租约实现、TTL、索引版本和待处理请求数量。
2. 停止接收新请求，排空模型推理、SQL、工具调用和消息消费；执行中的不确定 SQL 不进入恢复队列。
3. 创建目标命名空间和最小权限账号，先写入一条脱敏探针记录并从另一节点读取。
4. 迁移确定性会话、检查点、Agent 状态、记忆、推荐、SQL 审计和监控日志；每项保留源版本和幂等键。
5. 双读比较数量、版本、租约和 `projectId + operatorId` 隔离，确认敏感字段扫描无命中后开启灰度写入。
6. 灰度读取 10 分钟或一个完整业务窗口，检查恢复、租约争抢、过期清理和导出延迟，再切换全量读取。
7. 保留旧存储只读和回滚窗口；回滚只切换读取指针，不重复执行 SQL 或外部副作用。

## 故障排查表

| 现象 | 首查指标 | 处理 |
| --- | --- | --- |
| 跨节点读不到会话 | 存储命名空间、租约、上下文摘要 | 拒绝恢复请求，修复共享存储连接后重新校验版本 |
| 恢复令牌被拒绝 | checkpoint version、权限摘要、semantic version、幂等键 | 判断是否可重入；SQL 或工具副作用不确定时人工处理 |
| Agent 重复执行 | lease owner、heartbeat、idempotency key | 只释放过期租约，禁止依赖本地内存判断完成 |
| 向量召回为空 | embedding key、维度、索引版本、项目过滤 | 校验模型维度和索引重建状态，禁止静默回退本地向量 |
| 审计导出失败 | 本地日志数量、导出队列、稳定错误码 | 保留本地脱敏日志，重试导出；不影响问数响应 |
| 存储延迟升高 | P95/P99、连接池、热点项目、TTL 清理 | 限制新并发，扩容前先确认没有跨项目扫描 |

## 容量估算

使用以下量纲建立上限：活跃项目数、项目内操作人数、并发会话数、每会话消息数、每请求检查点数、Agent 节点数、每请求日志数、向量维度、文档数、索引副本数和保留天数。容量评审至少给出峰值写入、峰值读取、P95/P99 延迟、重建窗口、故障积压和两倍增长余量。

推荐拆分热点与历史：Redis 类存储承载短 TTL 会话、租约和 Agent 热状态，JDBC/审计平台承载可追溯历史，向量库承载版本化索引。三者的删除、撤销和项目隔离策略必须一致。

## 脱敏验证命令

```bash
rg -n -i 'password|secret|api[-_]?key|access[-_]?token|aes[-_]?key|chat_id|jdbc:[^ ]+://[^ ]+' docs/askdata/starter
```

该命令用于审查示例和文档文本；真实运行日志还要执行字段级 JSON 断言：token、密码、AES-Key、SQL 参数和原始模型响应必须不存在，项目和操作人只允许使用摘要或测试标识。
