# Known limitations and risks

- MP 与 MF 加密自动配置同时启用时，`FieldEncryptInterceptor`/`FieldDecryptInterceptor` 与 `EncryptorProperties` Bean 因类型相同由 `@ConditionalOnMissingBean` 互斥，仅注册一份；由于核心使用属性名定位（MetaObject），另一 ORM 的实体加解密仍正确。加解密配置统一使用 `fw.plus.mp-encrypt` 前缀。
- MF 加密为新增能力，无存量 Flex 加密使用者；适配层按 datachange 对称结构提供，行为已由 H2 端到端验证。
- 本 change 的实现代码在 dev 分支已落库（commit 8261aa3f 等），worktree 从 dev 创建时已包含实现；Build 阶段使用 `--no-code-reason` 推进，Verify 阶段基于 dev 已落库代码运行编译与测试验证。
