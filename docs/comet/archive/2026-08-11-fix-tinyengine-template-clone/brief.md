# Outcome

TinyEngine 用户能够从同租户模板稳定创建新应用，提交独立且合法的新应用编码；复制过程不受源模板成员角色限制，失败时只显示一次明确错误提示。

# Scope

- 模板创建表单新增必填应用编码，并限制为 1 至 20 位英文、数字、下划线或中划线。
- 后端在写入新应用前校验编码格式和当前租户内唯一性。
- 验证源应用属于当前租户且是模板后，通过内部 Mapper 读取源模板页面，避免把源模板成员权限错误应用到复制流程。
- 目标页面仍通过现有 PageService 创建，保留新应用 Owner 和目标应用权限校验。
- 模板创建接口失败时仅由全局 HTTP 层展示错误，组件不重复通知。
- 构建并重启 19080 样例服务，使用真实 MySQL 数据完成在线创建、复制和清理验收。

# Non-goals

- 不修改 AI 鉴权或模型配置。
- 不实现应用成员管理前端入口。
- 不改变应用角色权限矩阵、Owner 唯一规则或其他应用创建入口。
- 不复制源模板编码作为新应用编码，也不自动生成编码。

# Acceptance examples

- A1：用户在模板创建表单输入符合规则的新编码后，提交参数包含该编码而不是源模板编码。
- A2：编码为空、格式不合法或超过 20 位时，前端阻止提交；后端对绕过前端的同类请求也在写库前拒绝。
- A3：当前租户已存在相同应用编码时，模板创建在写入新应用前失败，且不留下应用、页面或角色数据。
- A4：源应用经验证是当前租户模板后，即使当前用户不是源模板成员，系统仍能读取并复制其页面；未验证的跨租户或非模板源应用不能使用内部读取路径。
- A5：模板创建成功后返回的新应用编码与请求一致，页面复制成功，并为当前真实用户创建且仅创建一个 `app_owner` 关系。
- A6：页面或 Owner 创建等任一步骤失败时，模板创建事务整体回滚，不留下部分应用数据。
- A7：模板创建接口失败时页面只显示一次由全局 HTTP 层产生的错误提示，不出现额外空白提示框。
- A8：部署到 19080 的样例服务后，真实登录用户可通过模板创建应用；验收创建的测试应用随后通过正式删除接口清理，关联应用角色数据同时删除。

# Constraints and invariants

- Java 源码兼容 JDK 8，不使用 Java 9+ API。
- 应用编码规则为 `^[A-Za-z0-9_-]{1,20}$`，唯一性范围为当前租户。
- 只有在源应用已验证为当前租户模板之后，复制服务才可绕过源应用成员角色读取模板页面。
- 新应用、复制页面和 Owner 创建继续处于同一事务。
- 目标应用页面写入继续使用现有服务层权限边界。
- 保留当前工作区其他未完成改动；本 change 只提交计划指定文件和正式 Comet 产物。

# Decisions

- 应用编码由用户在模板创建表单中明确输入，不自动派生或生成。
- 后端同时校验格式与租户内唯一性，数据库唯一索引继续作为最终并发保护。
- 源模板页面使用 `PageMapper.queryPageByApp` 内部读取；目标页面使用 `PageService.createPage` 写入。
- 失败通知统一交给全局 HTTP 拦截层，模板详情组件只收敛 Promise rejection。
- 用户已同意直接在当前 `dev` 工作区执行，并允许按既定计划使用子代理实现与独立审查。
