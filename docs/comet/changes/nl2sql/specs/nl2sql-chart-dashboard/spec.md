# nl2sql-chart-dashboard 完整目标规格（Shape 产物）

> **文档角色**：本文档是 Comet Native change `nl2sql` 的 capability `nl2sql-chart-dashboard` 的完整目标规格（Shape 产物，纯 markdown），承接 brief 中「## 验收示例 → ### 图表与看板（nl2sql-chart-dashboard）」小节。实现须以本文与 brief 的约束（D11/D42/D45 等决策）为验收基准。

`nl2sql-chart-dashboard` 依赖 `nl2sql-user-ui`：问数结果渲染能力、数据列表与看板均挂在用户端 UI 与对外 API 服务之上。能力覆盖：LLM 自动产出图表配置、前端按配置渲染（G2/S2 思路）、服务端图表图片渲染（对齐 SQLBot `g2-ssr`，Java 侧实现，不引入 Node 出图服务）、结果数据后端服务分页列表、dashboard 看板。

## 1. 范围

### 1.1 在范围

- LLM 依据问数结果自动产出图表配置（类型/轴，柱 column/条 bar/线 line/饼 pie/表 table），与问数记录一并保存。
- 前端按图表配置渲染图表（G2 思路的柱/条/线/饼，S2 思路的 TableSheet 表格），支持图表类型切换。
- 服务端按同一图表配置渲染 PNG 图片，供导出与非流式场景使用。
- 问数结果数据列表 API：后端服务分页（page/size），返回当前页数据与总行数，分页基址为记录库中的受行数限制结果集快照。
- dashboard 看板：用户将多次问数结果保存到看板，看板按配置布局展示图表。

### 1.2 非目标

- 不引入 Node.js 出图服务（D42：服务端出图用 Java 侧渲染实现，Build 时定方案，如 Java2D/Graphics2D、JFreeChart、Batik 等的任一，不搭建 g2-ssr Node 进程）。
- 不复刻 SQLBot `g2-ssr` 的 Node 代码或其 HTTP 服务形态。
- 不做看板的拖拽布局编辑器高级能力以外的扩展；首版看板为「保存问数结果即图表」的配置展示（见 §6）。
- 不存超出行数限制（默认 ≤1000 行）的全量结果集（沿用 brief 记录库约束）。
- 图表配置 schema 的变更走记录版本演进，首版 schema 以 §2 为准。

## 2. LLM 图表推荐（D42）

- 问数编排在 SQL 执行成功、结果集就绪后，由 LLM 基于「结果列结构 + 少量样例行 + 用户问题」产出图表配置 JSON；该产物作为问数记录的组成部分随记录保存，流式通道中随最终消息返回。
- 图表配置契约（语义冻结，对外 API 响应字段不得变更含义）：
  - `type`：`column | bar | line | pie | table` 之一
  - `title`：图表标题（可空）
  - `xAxis` / `yAxis`：类目轴/值轴字段名（table 类型为空）
  - `series`：可选的系列字段名（多系列时使用）
  - `label`：饼图标签字段，`value`：饼图数值字段
  - `columns`：table 类型的列定义（字段名/标题/类型）
- 解析约束：LLM 输出必须通过 JSON 契约校验（结构、type 枚举、轴字段必须存在于结果集列中）；校验失败时记录明确错误并降级为纯表格展示（`type=table`），不编造配置。
- 类型选择语义（提示词约束）：分类对比 → column/bar；趋势 → line；占比 → pie；无明显维度/多维明细 → table。提示词模板版本化管理（沿用 nl2sql-core 的提示词版本能力）。

## 3. 前端图表渲染（G2/S2）

- 用户端 UI 按记录中的图表配置渲染：柱/条/线/饼使用声明式图形语法渲染（对标 AntV G2 的配置即选项形态，前端实现不强制依赖 @antv/g2 npm 包，可用 ECharts 等同类库实现同构语义）；表格使用 S2 TableSheet 同款语义（大数据量列式表格，支持排序/筛选基础交互）。
- 图表切换：用户在 column/bar/line/pie/table 间切换时，按同一结果数据重新映射轴配置渲染；无法映射某类型（如单值结果切饼图）时给出提示，不渲染错误图表。
- 无图表配置（LLM 未产出或降级）时默认展示 table。
- 前端渲染产物与服务端出图（§4）使用同一图表配置契约，保证「所见即所得」的近似一致。

## 4. 服务端出图（D42，不引 Node 服务）

- 能力目标对齐 SQLBot `g2-ssr`：输入图表配置 + 数据，输出 PNG。
- 实现：Java 侧渲染器 `ChartImageRenderer`（接口）+ 默认实现，按 `type` 分发至 column/bar/line/pie 各渲染（对应 SQLBot g2-ssr `charts/{column,bar,line,pie}.js` 的等价图形语义），table 类型可出表格 PNG 或返回不支持错误（Build 时定）。
- 默认参数：宽 640、高 480、PNG、白底（对齐 g2-ssr `base_options`）；可通过 API 参数覆盖。
- 对外消费形态（二选一或兼具，Build 时定）：结果导出时内联 PNG 附件；非流式 API 返回 base64 PNG 字段或独立图片下载端点。
- 不搭建任何 Node.js 进程/页面；字体类问题使用框架已有字体资源或 JDK 内置字体兜底。

## 5. 数据分页列表（D45，后端服务分页）

- 对外 API 接受 `page` / `size` 参数（默认 page=1，size=20，size 上限受行数限制快照规模约束），返回当前页行数据与总行数 `total`（即快照总行数，可能小于业务库真实总行数——受行数限制上限截断）。
- 分页基址：记录库保存的**结果集快照**（默认 ≤1000 行，见 brief 约束与 D45）。历史回看与首次返回的翻页走同一快照，不再查业务库。
- 记录库存储：问数记录保存 SQL + 结果集快照（行数据）+ 总行数 + 图表配置，用于历史回看、分页翻页与看板重展示；不存超出上限的全量结果集。
- 记录写入与快照裁剪在编排完成后同步完成；快照为空（无结果）时分页 API 返回空页与 total=0。

## 6. dashboard 看板（D11）

- 用户可将多次问数结果（记录）加入看板；看板项保存：来源记录引用、展示用图表配置（可用记录中的配置，也可被用户调整类型/轴）、标题、布局位置。
- 看板展示：按配置逐项渲染图表（复用 §3 同一渲染组件与同一图表配置契约）；数据取自各来源记录的结果集快照（不回查业务库）。
- 看板为按看板 id 组织的配置集合，支持查看与删除板块；首版不含定时刷新与复杂权限分级（看板可见性沿用问数服务整体 Sa-Token 鉴权）。
- 管理端/用户端入口：看板页面挂在用户端 UI（D11/D7 语义，不进 magic 控制台）。

## 7. 约束与非目标

- Java 1.8 语法基线（禁 Java 9+ API：`List.of`、`Map.copyOf`、`Optional.orElseThrow` 等）；包归 `com.xiongx9527.fw.plus.*`。
- 服务端出图纯 JVM 实现，不引入 Node 运行时依赖（D42）。
- LLM 图表配置必须 JSON 契约校验，失败降级 table，不编造。
- 分页与看板数据均来自受行数限制的快照，不回源业务库、不突破 1000 行上限。
- 图表配置契约字段语义冻结；演进走记录版本字段，不改含义。
- D11 首版全功能对齐中的 dashboard 范围以本节为准；后续单独 change 可扩展布局编辑/定时刷新。
