# nl2sql-security 数据权限 完整目标规格（Shape 产物）

> **文档角色**：本文档是 Comet Native change `nl2sql` 的 capability `nl2sql-security` 的目标规格，承接 `brief.md`「## 验收示例 → ### 数据权限（nl2sql-security）」小节与决策 D2/D14/D19/D25/D36。纯规格文档，不含代码实现。验收以本文各章节的 Scenario 描述与 brief 同节索引行为最低要求为准。

数据权限的定位：fw-plus 框架**不内置用户/角色/部门模型**（非目标），数据权限采用**回调模式**——框架把原始 SQL + 用户身份标识透传给业务注册的回调，由业务返回转换后的 SQL；框架负责执行前只读复检、fail-closed、提示词层权限约束注入、列级脱敏与 SQL 传递安全。

## 1. 数据权限范围

- 数据权限覆盖**行级**（通过回调在 SQL 中附加过滤条件实现）与**列级脱敏**（结果集序列化时统一处理，D36）两个层面，同一策略 SPI 演进承载。
- 权限策略的生效对象维度（用户/部门/角色等）**不由框架定义**：策略 SPI 将当前用户身份标识（UserContext）原样透传给业务实现，由业务解释并返回可见数据条件；策略规则中引用的主体同样由业务解释（对齐非目标「角色、用户体系完全由业务决定」）。
- 用户标识来源：用户端认证走框架 Sa-Token 授权服务端（D14），登录态上下文即 UserContext；对外 API/MCP 通道沿用各自认证体系后派生的用户身份。
- 框架侧始终兜底的安全底线（不因回调存在与否放宽）：SQL 强制只读（拦截 DML/DDL）、强制外层行数限制、只读数据库账号兜底、闲聊分支 agent 不携带任何工具。

### 无回调放行

未注册任何 SQL 回调时，LLM 生成的 SQL 原样执行；只读校验、行数限制注入与结果集脱敏流程仍完整生效。此为开箱即用基线。

## 2. 回调 SPI 契约（同进程 Java bean 与跨进程 HTTP 两实现）

统一契约：框架在 SQL 执行前调用回调，输入为**原始 SQL、UserContext（用户标识透传）、表元数据**；输出为业务转换后的 SQL 字符串。同契约提供两种实现（D25）：

- **同进程 SPI（Java bean）**：业务实现一个框架规定的回调接口（`com.xiongx9527.fw.plus.*` 包，例如 `SqlPermissionCallback`），注册为 Spring bean 后由框架在同进程内直接调用；进程内调用无传输环节，无需传递加密。
- **跨进程 HTTP 回调**：业务系统独立部署，框架以 HTTP 调用约定（请求/响应 JSON 结构与 bean 入参/返回值语义一致）把原始 SQL + UserContext + 表元数据 POST 给业务回调端点，业务返回转换后 SQL；开关与密钥对配置见 §6。

管理端可配置每问数实例的回调实现形态与目标（bean 名 / HTTP 地址），切换在配置刷新后生效（§8）。未配置回调即 §1 基线。

### 回调转换

业务注册了 SQL 回调时，框架把生成的原始 SQL + 用户标识交给回调，执行回调返回的 SQL，并保存为问数记录。

## 3. fail-closed 与只读复检

- 回调返回的 SQL **重新执行只读复检**：必须是合法的单语句 SELECT/查询语句；非 SELECT（含 DML/DDL/多语句/存储过程调用等）一律拒绝执行。
- **fail-closed**：回调抛异常、超时、返回空串/非法 SQL、或复检失败时，拒绝执行并向用户返回明确错误（含原因类别），不编造结果、不回退执行原始 SQL。
- 框架侧原始 SQL 的只读校验与行数限制注入在回调前已生效；回调返回 SQL 经复检后，外层行数限制按同一规则约束（默认 1000，不进子查询）。
- 人工调整 SQL（改后重执行）同样过只读校验与数据权限回调（D44）；只读复检失败时拒绝执行。

### fail-closed

回调抛异常或返回空/非 SELECT SQL 时，拒绝执行并明确报错；错误信息进入对话记录与审计，不向用户透出业务侧异常堆栈。

## 4. 提示词约束注入

- 在 SQL 生成提示词中注入**可配置的权限提示**（例如要求 SQL 自带租户过滤条件、不查询无权限表等），目的是减少回调改写量、让 LLM 生成的 SQL 尽量已符合权限约束。
- 提示词约束是**减量优化**，不替代回调与执行前复检：即使提示词注入生效、LLM 已生成带条件 SQL，回调与只读复检仍强制执行。
- 权限提示文案纳入提示词版本化管理（与自定义提示词同一版本机制），修改后可回滚。

## 5. 列级脱敏（D36）

- 权限回调演进携带**列级脱敏规则**（与行级同一 SPI）：业务在返回转换后 SQL 的同时可声明结果列的脱敏策略（如手机号、身份证、邮箱、银行卡等模式的掩码规则）。
- 结果集序列化时统一按列级规则脱敏后再返回用户端/API 响应、图表数据与导出文件；导出（Excel/CSV/PNG）沿用同一脱敏结果。
- 记录库保存的结果集快照按脱敏后的形态存储；历史回看与分页数据与实时结果一致。
- 未配置列级规则时该列原样输出；脱敏规则变更按配置刷新语义生效。

## 6. SQL 传递安全（D19/D25）

- **加密开关**：管理端配置项控制 SQL 载荷传递是否加密；开关启用时以应用层加密为安全保障（不要求 TLS，传输协议由部署环境自行决定）；开关关闭时明文传递，传输保护由部署环境自行负责。本地 SPI（Java bean）为进程内调用，无传输环节。
- **密钥对与签名**：加密开关启用且回调为 HTTP 跨进程调用时，SQL 载荷经非对称加密（RSA/SM2 混合加密：框架用业务公钥加密载荷、业务私钥解密；响应可反向加密）+ 私钥签名防篡改。密钥对由管理端生成与管理（生成/轮换/公钥分发均在管理端完成，私钥不回显）。
- **展示控制**：用户端 UI 默认**不展示原始 SQL 明文**，可按实例配置开启；SQL 相关内容在传输中以加密/脱敏形态出现。
- **日志控制**：日志中 SQL 全文按日志级别脱敏/控制，默认不输出完整 SQL；ReAct 工具调用轨迹入审计日志时同样脱敏。
- **记录库加密**：记录库中的 SQL 字段支持可选加密存储（实例配置）。

### SQL 传递安全

回调为远程调用且加密开关启用时，SQL 载荷经非对称加密（管理端生成的密钥对）+ 签名传递；开关关闭时明文传递；用户端默认不展示原始 SQL 明文；日志不输出完整 SQL。

## 7. 敏感配置加密

- 管理端保存数据源密码、LLM api-key、回调密钥（私钥/签名密钥）等敏感字段时，以加密形态写入共享配置存储（数据库表）；API 服务读取时解密后使用。
- 共享配置存储 DDL 由框架统一提供并带 schema 版本；分应用部署时版本不匹配明确报错。
- 私钥在管理端不回显，仅支持轮换与重新生成。

### 敏感配置加密

管理端保存数据源密码/LLM api-key 等敏感字段时，以加密形态写入共享配置存储；API 服务读取时解密；任何列表/详情接口不回显明文。

## 8. 策略管理与配置刷新

- 管理端（magic 插件 toolbars 页签，独立「数据权限策略管理」模块）支持策略 CRUD、规则绑定（绑定到问数实例/资源）、启停、回调函数（bean 或 HTTP 地址）的新增/修改/停用。
- 配置机制（D25）：配置缓存 + 变更刷新——同进程事件通知；分应用部署时版本号轮询或 Redis 广播；策略/回调/加密开关变更后下一次问数执行按最新配置生效。
- 管理端操作审计：策略与回调配置变更记录操作人与变更前后快照，可查询。

### 策略管理

管理端新增/修改/停用数据权限策略或回调函数后，问数执行按最新配置生效；停用策略后该实例回到「无回调放行」基线或剩余生效策略的组合语义。

## 9. 租户隔离示例

业务回调用法示例（文字描述，非代码）：业务注册 HTTP 回调，UserContext 中携带租户标识；回调在原始 SQL 外层包裹/追加 `tenant_id = ?` 过滤条件后返回；框架只读复检通过后执行。效果：该用户只能看到本租户数据，越租户数据不可见；未注册回调的实例则无此隔离，由业务评估是否可接受。

### 租户隔离示例

业务的回调按用户租户改写 SQL（附加 tenant_id 条件）时，越租户数据不可见；改写产物必须通过框架只读复检。

## 10. 约束与非目标

- Java 1.8（禁 `List.of()` 等 Java 9+ API）、Spring Boot 2.7.18、包名 `com.xiongx9527.fw.plus.*`。
- 框架不定义用户/角色/部门模型；策略生效对象由业务经 SPI 解释（D14/D2）。
- 不复制 SQLBot 代码（类 GPLv3 约束），仅对齐功能设计。
- 提示词约束不替代回调与复检；fail-closed 语义不可配置关闭。
- 回调超时、空返回、非法 SQL 的报错文案不得泄露业务侧堆栈与密钥。
