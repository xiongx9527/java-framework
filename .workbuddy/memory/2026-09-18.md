## agentic/core 的 failsafe 配置改为 Maven 官网语义（同日续）

用户要求「按照官网的来」：把 agentic 里 `combine.self="override"` + 3 个 execution 的写法，改成 Maven POM Reference 文档口径。

官网依据（已抓取 maven.apache.org/pom.html 与 guide-configuring-plugins.html 原文）：
- 「Executions with the same id from different POMs are overwritten by child configuration」；execution 无 `<id>` 时即 `default`。
- `<inherited>` 只在父 POM 中生效（"This element is only meaningful to parent POMs"），无法用来屏蔽 spring-boot 父 POM 的 execution。
- goal 自带默认阶段绑定，未绑定任何阶段的 goal「simply won't be executed」。
- plugin 级 `<configuration>` 自 Maven 3.3.1 起对所有 execution 生效，无需逐 execution 重复。

改法（core 与 agentic 一致）：failsafe 只留 `<configuration>`（plugin 级放 `includes` 与 `systemPropertyVariables`）+ **一个** `<execution><id>default</id><goals>integration-test,verify</goals></execution>`，不写 `<phase>`、不再用 `combine.self`。
- 删除了 core 的 `core-overlay-packaging-it` / `core-overlay-packaging-verify` 与 agentic 的 `agentic-integration-test` / `agentic-verify`（共 4 个 execution），删除了 3 处重复的 `systemPropertyVariables`。
- 效果：core 的 IT 从「跑两遍」变成一遍（此前 `default` 与 `core-overlay-packaging-it` 各跑一次）；failsafe 每次构建的 integration-test goal 触发次数从 4 → 2。
- 契约测试 `OverlayAllowlistContractTest#failsafeLifecycleHasSeparateIntegrationTestAndVerifyExecutions` 原本把旧的 3-execution + `combine.self` 形态写死，已重写为 `#failsafeLifecycleOverridesInheritedDefaultExecutionBySameId`，改为断言新形态（1 个 execution、显式 id=default、goals=integration-test+verify、无 `combine.self`、无显式 `<phase>`）。
- **core 的 `pluginManagement > shade > <executions combine.self="override"/>` 保留并加注释**：经核实 spring-boot-starter-parent 会向 shade 注入 `${start-class}` ManifestResourceTransformer 等 Spring Boot 专用配置，必须抑制，不能按 failsafe 的方式一并简化。

### 核心设计张力：record 注解传播 vs 两道门禁
beta30 把 `@JsonInclude`/`@JsonProperty` **直接写在 record 组件上**（`AgentInvocation`、`DefaultAgenticScope.AgentMessage`）。javac 会把 record 组件注解传播到 **字段 + 规范构造器参数 + 隐式访问器**；显式覆写的访问器（`AgentInvocation.output()`）**不传播**。Java 8 等价类必须手工复刻这个分布，否则两侧同时炸：
1. `AgenticPublicApiParityTest` 逐条比对 ASM 注解集合（含参数注解、注解元素值），多一个少一个都失败；
2. `Task2a1/Task2a2/Task2a2Runtime` 孤立 harness 会因缺少 import 编译失败。
- **结论：不要给 Java 8 等价类加 `@JsonCreator`。** 上游 record 的规范构造器由 Jackson **隐式识别**（唯一非默认构造器 + 参数带 `@JsonProperty`）；加了会与上游注解集合不等而 parity 失败，去掉后 `AgenticSuspensionRecoveryTest` / `AgenticHumanInTheLoopRootBehaviorTest` 的 JSON 往返依旧全绿。
- 保留 `@JsonProperty` 只加到 **隐式生成的访问器**上（`agentType()/agentName()/agentId()/input()` 与 `AgentMessage` 三个访问器），**不要加到被覆写的 `output()`**。
- `DefaultAgenticScope` 的 `@JsonCreator` 属于上游既有（在 `(memoryId, kind)` 构造器上），必须保留。

### 决定性发现：孤立 harness 其实继承 surefire 的 `java.class.path`
`Task2a1/2/3RuntimeContractTest` 调 `compiler.getTask(...)` 时**没有**传 `-classpath`，于是 `JavacFileManager` 回落到默认类路径 = 当前 JVM 的 `java.class.path`（即完整 surefire 测试类路径，含 jackson-annotations）。所以「纯 JDK 编译」指的是**产物只由 harness 目录 + JDK 组成**（`new URLClassLoader(urls, null)`），编译期并不是零依赖。⇒ 生产源码里出现 Jackson 注解不会让 harness 编译失败，**缺 import 才会**。

### Maven 踩坑：`${project.parent.basedir}` 在插件参数里不插值
- 现象：antrun `<replace value="${project.parent.basedir}/...">` 把**字面量** `${project.parent.basedir}` 写进 classpath 清单，IT 报 `runtime classpath entry is not a file: .../${project.parent.basedir}/...`。同一个 value 里的 `${revision}` **却正常插值**。
- 结论：插件配置求值阶段能解析 `${project.basedir}`/`${project.build.directory}`/`${settings.*}`/POM 属性，但**解析不了 `${project.parent.basedir}`**。改回 `${project.basedir}/../fw-plus-ai-langchain4j-core/target/...` 即通过（IT 侧 `toAbsolutePath().normalize()` 会消掉 `..`）。
- 该坑此前未被发现，是因为 core 的 `target/` 一直是空的、IT 从未真正跑起来；`clean` 后 core 必须先 `package` 出 jar，antrun 的替换目标才存在。
