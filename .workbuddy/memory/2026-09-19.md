# 2026-09-19 — POM 层精简（"还是太复杂了" → POM）

用户的指令是「继续改吧，还是太复杂了」。经追问确认，要砍的是 **POM 层**（不是契约测试、不是 record 兼容层、不是上游回移清单）。
方向：把 `fw-plus-ai-langchain4j` 层以及全仓 POM 里「写了等于没写」的东西全删掉，让这一层跟仓库里其它工程一样朴素。

## 结果量化
- 全仓改动 **160 个 POM**，总行数 **12294 → 11483（-811 行）**。
- `fw-plus-ai-langchain4j` 层 22 个 POM：`pom.xml` 143→36、`agentic` 191→90、`core` 158→193（净增 35，全是注释 + 一个必需的 disable execution，见下）、其余各 -6 ~ -14。

## 具体改动
1. **全仓删除死属性 `main.basedir`**（139 个 POM）。删除前做了严格引用检查：`os.walk` 遍历全仓非 target/docs 的 pom，正则 `.{0,40}main\.basedir.{0,40}`，排除「纯 `<main.basedir>…</main.basedir>` 定义且不含 `${`」的形态 → **非定义用法命中 0**。连同因此变空的 `<properties>` 块一起删，并规范多余空行。
2. **删除冗余 `<relativePath>../pom.xml</relativePath>`**：这是 Maven 默认值，写了不改变任何行为。**唯一保留**的是 `fw-plus-ai-langchain4j-adapter` 的 `../../../fw-plus-parent`（非默认路径）。
3. **删除被 BOM 管理的依赖 `<version>`**：`dev.langchain4j:*` 由 `langchain4j-bom` 管理、`com.xiongx9527.fw.plus:*` 由 `fw-plus-dependencies` 管理，两层 parent 链都继承。用 `dependency:tree -Dincludes=…` 实测确认省略版本后仍能解析。**保留 `<type>test-jar</type>` 依赖的版本**（test-jar 不在 dependencyManagement 的匹配键内，删了会解析失败）。
4. **cassandra**：删掉本地 `<datastax-java-driver.version>` 属性与依赖上的 `${…}`（BOM 已管）。
5. **infinispan**：删掉了重复的本地 `<infinispan.version>` 属性，但 **`infinispan-bom` 的 import 必须保留** —— 删掉会让传递依赖 `infinispan-commons` 从 13.0.22 掉到 13.0.20（用 `dependency:list` 前后 diff 实测）。这是本轮唯一一次「删了会变坏」的案例。
6. **core 的 `pluginManagement > shade > <executions combine.self="override"/>` 删除** —— 用 `help:effective-pom` 导出前后有效 POM，逐行 `difflib.unified_diff` 对比 shade `<plugin>` 块，**完全一致**，证明它是纯冗余。真正起作用的是本模块 shade 里 `<id>default</id><phase>none</phase>` + `__disabled__` artifactSet 的空 execution（同 id 顶掉 spring-boot-starter-parent 注入的 Spring Boot transformers）。
   - 反例已实测：把 `combine.self="override"` 挪到本模块 `<executions>` 上，继承来的 execution 会以 package 阶段复活、把全部依赖打进产物。**要清空继承 execution 只能靠「同 id 空 execution + phase=none」，不能靠 combine.self。**
7. **agentic 的 antrun 删除**，`dependency-plugin + antrun` 两插件收成一个：清单里的 core 仍指向本地仓库快照，替换动作改由测试侧就地进行（`AgenticOverlayPackagingIT.runtimeJars` 把 `AgenticTestPaths.ownerJarInLocalRepository()` 换成 `resolve("agentic.owner.jar")`）。
8. 聚合器 `pom.xml` 收敛为纯聚合器（`packaging=pom` + 21 个 `<module>`），不再重复声明 core 的 shade/依赖；修正了一处 `<module>` 缩进。

## 续一：全仓删除 `<scope>compile</scope>`（222 处）

`compile` 是 Maven 依赖的默认 scope，写出来等于没写。全仓 31 个 POM、222 处，其中 `fw-plus-boot-autoconfigure` 一个文件就 106 处（该 POM 822 → 712 行）。

### 风险与判定
不能无脑删：若某 GA 在父链的 `dependencyManagement` 里被钉成 `provided`/`test`，省略 `<scope>` 会**继承**那个非 compile 值。实测有效 POM 的 dependencyManagement 里确有 14 条非 compile 条目（`infinispan-component-annotations`/`protostream-processor` 为 provided，一批 wiremock/arquillian 类为 test）。

判定手段是**地面真值**，不是静态猜：
- 对 19 个受影响模块跑 `dependency:list -DincludeScope=test`（输出含每条依赖解析后的 scope），删除前后各一次，`difflib` 逐行 diff → **18 个模块结果完全一致，0 处变化**。
- 剩下 1 个（`fw-plus-magicapi-spring-boot-starter-sample`，1 处 `apollo-client`）因 Boot 层既有编译失败、兄弟制品未安装而无法解析依赖，改用 `help:effective-pom` 静态判定：`apollo-client` 在 dependencyManagement 中**无 scope** → 省略即 compile，安全。
- 探测脚本：`/tmp/scope_probe.py`（mode: before/after/diff）。
